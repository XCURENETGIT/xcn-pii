# 숫자형 개인정보 비표준 구분자 탐지 PoC

## 정책

이 기능은 PoC 단계에서 처리 성능과 과탐보다 탐지 재현율을 우선한다. 숫자 그룹 사이에 `&`, `/`, `.`, 작은따옴표, 백틱, `|`가 있으면 라벨 유무와 관계없이 후보로 수집한다. 각 위치에 서로 다른 구분자를 사용한 혼합 형식도 허용한다.

기존 하이픈·공백·붙여쓰기 패턴은 그대로 유지된다. 주민번호, 사업자등록번호, 카드번호, 법인등록번호, IMEI처럼 체크섬이 있는 타입은 비표준 구분자를 제거한 뒤 기존 체크섬 검증을 통과해야 한다.

## 적용 타입

| 타입 | 내용 | 추가 검증 |
| --- | --- | --- |
| `SN`, `FN` | 주민등록번호, 외국인등록번호 | 날짜·성별 코드·체크섬 정책 |
| `SSN` | 미국 Social Security Number | area/group/serial 구조 |
| `DN` | 운전면허번호 | 12자리·반복값 제외 |
| `MN` | 국내 전화번호 | 국내 지역·이동전화 prefix와 길이 |
| `BRN` | 사업자등록번호 | 체크섬 |
| `BN` | 계좌번호 후보 | 10~16자리 |
| `CN` | 카드번호 | 카드 BIN·길이·Luhn |
| `CPN` | 법인등록번호 | 체크섬 |
| `IMEI` | 단말기 IMEI | 15자리·Luhn |
| `VN_MN` | 베트남 휴대전화 | 이동전화 prefix |
| `VN_CCCD` | 베트남 CCCD | 12자리·지역 코드 |
| `VN_TIN` | 베트남 세금번호 | 10자리 또는 13자리 |
| `VN_SI` | 베트남 사회보험번호 | 10자리 |

차량번호(`CRN`), 여권번호, IP, MAC처럼 문자 또는 기존 구분자 자체가 의미 구조인 타입은 숫자형 공통 후보의 출력 타입에서 제외한다.

## 타입 중복 처리

같은 숫자 길이가 여러 타입에 해당할 수 있다. 후보 앞 48자 안에서 가장 가까운 타입 라벨을 찾아 해당 타입에 명시적 문맥 우선순위를 부여한다.

```text
계좌번호 4716/1292.3626|7849   -> BN
카드번호 4532/1234.5678|9014   -> CN
CCCD 079/213/456/789            -> VN_CCCD
운전면허번호 11.22.333333.44    -> DN
```

라벨이 없거나 라벨로 구분할 수 없으면 기존 타입 간 우선순위를 적용한다. 따라서 탐지는 되더라도 사용자가 의도한 세부 타입과 다르게 분류될 수 있다.

## PoC 과탐 주의

점이나 슬래시로 구분된 IP, 날짜, 버전, 파일 경로, URL 경로와 쿼리도 숫자 길이·구조가 맞으면 개인정보 후보가 될 수 있다. 이는 탐지 우선 요구에 따른 의도된 PoC 동작이다. 운영 전환 시에는 타입별 라벨 또는 문맥 필수화, 허용 그룹 형태 제한, URL/IP/날짜 제외 처리를 다시 적용해야 한다.
