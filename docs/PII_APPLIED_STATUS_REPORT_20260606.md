# xcn-pii 개인정보 탐지 적용 현황

작성일: 2026-06-06

## 1. 검토 기준

이 문서는 `xcn-pii` 프로젝트의 현재 소스 기준으로 개인정보 탐지 항목별 적용/미적용 상태와 구현 내용을 정리한 자료이다.

검토 기준 파일:

| 구분 | 파일 |
| --- | --- |
| 기본 룰셋 | `app/rules/_ruleset.yaml` |
| 엄격 룰셋 | `app/rules/_ruleset_strict.yaml` |
| 탐지 룰 | `app/rules/*.yaml` |
| 체크섬/구조 검증 | `app/pii_engine/common.py` |
| 탐지기/후처리 | `app/pii_engine/detectors.py` |
| 문맥 필터 | `app/rules/context.yaml`, `app/pii_engine/context_filters.py` |
| HTTP API | `app/main.py` |
| 응답 스키마 | `app/schemas.py`, `app/response_builders.py` |
| 첨부파일 텍스트 추출 | `app/file_text_extract.py` |
| 대용량 입력 분할 | `app/pii.py` |
| gRPC/LB 구성 | `README_GRPC.md`, `docker-compose*.yml`, `infra/*` |

상태 기준:

| 상태 | 의미 |
| --- | --- |
| 적용 | 기본 룰셋 또는 현재 API 응답 기준으로 실제 사용 가능 |
| 부분 적용 | 일부 형식/조건은 지원하지만 요구 항목 전체는 미충족 |
| 미적용 | 현재 코드/기본 룰셋/API 응답 기준으로 기능 없음 |
| 확인 필요 | 외부 바이너리/배포 구성/운영 설정에 따라 결과가 달라짐 |

## 2. 기본 탐지 항목 요약

현재 `default` 룰셋의 실제 탐지 파이프라인은 다음 9개 항목이다.

| 응답 키 | 의미 | 기본 룰셋 | strict 룰셋 | 문맥 필터 대상 |
| --- | --- | --- | --- | --- |
| `SN` | 주민등록번호 | 적용 | 적용 | 적용 |
| `SSN` | 미국 Social Security Number | 적용 | 적용 | 적용 |
| `DN` | 운전면허번호 | 적용 | 적용 | 적용 |
| `PN` | 여권번호 | 적용 | 적용 | 적용 |
| `EML` | 이메일 주소 | 적용 | 적용 | 미적용 |
| `CN` | 신용/체크카드 번호 | 적용 | 적용 | 적용 |
| `MN` | 전화번호/휴대폰 번호 | 적용 | 적용 | 미적용 |
| `BRN` | 사업자등록번호 | 적용 | 적용 | 미적용 |
| `BN` | 계좌번호 후보 | 적용 | 적용 | 적용 |

다음 룰 파일은 존재하지만 기본/strict 룰셋의 `steps`와 `rule_files`에 포함되어 있지 않아 현재 기본 API 응답에는 나오지 않는다.

| 응답 키 | 의미 | 현재 상태 |
| --- | --- | --- |
| `AN` | 주소 | 룰 파일 존재, 기본 파이프라인 미포함 |
| `IP` | IP 주소 | 룰 파일 존재, 기본 파이프라인 미포함 |

현재 HTTP 응답 스키마는 `SN`, `SSN`, `DN`, `PN`, `MN`, `BRN`, `BN`, `CN`, `EML` 9개 타입을 반환하도록 정의되어 있다.

## 3. 요청 항목별 적용 현황

| 요청 항목 | 상태 | 현재 구현/판단 |
| --- | --- | --- |
| 주민등록번호: 표준형식 | 적용 | `YYMMDD-XXXXXXX` 형식 탐지 |
| 주민등록번호: 하이픈 없이 작성 | 적용 | 13자리 연속 숫자 탐지 |
| 주민등록번호: 공백 및 구분자 삽입 | 부분 적용 | 하이픈 형식과 compact 형식은 지원하나 `890512 - 2054508`처럼 하이픈 주변 공백이 있는 변형은 기본 SN 패턴에서 직접 지원하지 않음 |
| 주민등록번호: 존재불가 개월/일자 | 적용 | 월 1~12, 일자 및 실제 날짜 유효성 검증 |
| 주민등록번호: 체크섬 | 적용 | 기존 부여체계는 체크섬 검증, 2020-10-05 이후 생년월일 후보는 임의번호 체계로 보고 체크섬 실패만으로 제외하지 않음 |
| 운전면허번호 | 부분 적용 | `00-00-000000-00`, 공백 구분, 12자리 compact 형식 탐지. 전용 체크섬은 없음 |
| 운전면허번호 유사 코드 오탐 검증 | 부분 적용 | all-zero 제외, 문맥 필터로 완화. 제품/업무 코드 전용 화이트리스트는 없음 |
| 여권번호 | 부분 적용 | 영문 1~2자 + 숫자 7~8자리 탐지. 여권 전용 체크섬은 없음 |
| 제품 모델명 오탐 검증 | 부분 적용 | 여권 문맥 필터가 있으나 제품 모델명 전용 제외 룰은 확인되지 않음 |
| 외국인등록번호 체크섬 | 적용 | `FN` 타입으로 분리. 주민등록번호 후보 스캔 후 뒷자리 첫 숫자 5~8을 외국인등록번호로 분류 |
| 사업자등록번호 체크섬 | 적용 | `BRN` 전용 detector/rule/checksum 적용. 체크섬 실패 값은 BRN 결과에서 제외하고 BN으로도 재분류하지 않음 |
| 차량번호 | 미적용 | 차량번호 전용 룰 없음 |
| 전화번호 | 적용 | 국내 전화/휴대폰, 국제번호, 하이픈/공백/점 일부 지원 |
| 계좌번호 | 부분 적용 | 10~14자리 계좌 후보 탐지와 문맥 필터 적용. 은행별 구조 파일은 있으나 기본적으로 비활성이고 계좌 체크섬 검증 없음 |
| 법인등록번호 | 미적용 | CPN/법인등록번호 전용 룰 없음 |
| 가짜 숫자 | 부분 적용 | 주민번호/카드/전화/SSN 일부 구조 검증으로 제거. 모든 임의 숫자/업무번호 제거는 보장하지 않음 |
| 신용카드 번호 | 적용 | 14/15/16자리 카드, 브랜드 prefix, Luhn 검증 적용 |
| 카드 구분자 없는 16자리 | 적용 | 구분자 없는 16자리 카드 패턴 지원 |
| 휴대폰 번호 | 적용 | `010-1234-5678`, `010 1234 5678`, `01012345678`, 한글 숫자 일부 지원 |
| 이메일 주소 | 적용 | local/domain/TLD 구조 검증 적용 |
| 관청 소재지 주소 | 부분 적용 | 주소 룰(`AN`)은 존재하나 기본 룰셋/API 응답에 미포함 |
| 건강/진료 정보 | 미적용 | 민감정보 주제 분류 전용 룰 없음 |
| 종교/정치 성향 | 미적용 | 민감정보 주제 분류 전용 룰 없음 |
| 복합 PII | 부분 적용 | 같은 입력에서 여러 타입 동시 탐지 가능. 복합 위험도 산정/시나리오 판정은 없음 |
| 인사발령 통지문 | 부분 적용 | 문맥 라벨, 이름+PII 행, 표 헤더/반복 구조로 일부 탐지 가능. 인사발령 문서 전용 룰은 없음 |
| 명단 엑셀 가공 | 부분 적용 | 첨부파일 텍스트 추출 후 표 헤더/반복 행 보조 판정 가능. 원본 엑셀 셀 구조를 직접 파싱하는 로직은 아님 |
| 특수문자 삽입 | 부분 적용 | 일부 타입은 하이픈/공백/점/한글 숫자/zero-width 문자 제거에 대응. 임의 특수문자 삽입 전체 대응은 아님 |
| 멀티턴 분할 입력 | 미적용 | API는 단일 요청 텍스트 기준이다. 여러 턴을 조합해 재구성하지 않음 |
| 숫자 사이 공백 | 부분 적용 | 전화/운전면허/카드/계좌 일부 지원. 주민번호는 하이픈 주변 공백 등 일부 변형 미지원 |
| 마스킹 전송 | 부분 적용 | 원문에 충분한 숫자가 남아야 탐지 가능. `900101-1******` 같은 마스킹 값 복원/차단은 없음 |
| 탐지 지연시간 | 적용 | gRPC 벤치마크 기준 문서 존재. direct mode 2991자, 100건, concurrency 10 기준 p50 232.86ms, p95 270.13ms 기록 |
| 대용량 프롬프트 | 적용 | `PII_SPLIT_*` 환경변수 기반 chunk 분할/overlap/merge 처리 |
| 탐지 정확도 | 부분 적용 | 구조 검증, 체크섬, 문맥 필터, 회귀 테스트 일부 존재. 전체 항목별 정량 정확도 리포트는 별도 산출 필요 |
| 예외처리/화이트리스트 | 부분 적용 | 룰/문맥 설정으로 전역 조정 가능. 관리자 화면에서 특정 직원/서비스 단위 예외처리하는 기능은 없음 |
| 지급계좌 | 부분 적용 | `BN` 계좌 후보로 탐지 가능하나 지급계좌 전용 분류는 없음 |
| 개인메일 | 적용 | `EML`로 탐지 |
| 공개 전화번호 | 부분 적용 | `MN`으로 탐지. 공개/비공개 전화번호를 구분하는 화이트리스트는 없음 |
| 공개 주소 | 부분 적용 | 주소 룰은 존재하나 기본 미포함. 공개/비공개 주소 구분 기능 없음 |
| 문맥 기반 | 적용 | `SN`, `SSN`, `DN`, `PN`, `BN`, `CN`에 embedding/hybrid 문맥 필터 적용 |
| 영문 프롬프트 | 부분 적용 | SSN, driver license, passport, account, card, email 등 영문 라벨 포함. 전체 영문 민감정보 시나리오 분류는 아님 |
| Luhn: 주민등록번호 | 미적용 | 주민등록번호는 Luhn이 아니라 한국 주민등록번호 체크섬을 사용 |
| Luhn: 여권번호 | 미적용 | 여권번호 Luhn/전용 체크섬 없음 |
| Luhn: 외국인등록번호 | 해당 없음 | Luhn 대상이 아니며, `FN`은 주민등록번호 계열 체크섬 정책을 적용 |
| Luhn: 운전면허번호 | 미적용 | 운전면허번호 전용 Luhn/체크섬 없음 |
| Luhn: 복합체크섬 교차 검증 | 미적용 | 복수 체크섬 교차 검증 로직 없음 |
| 첨부파일 내 개인정보 탐지 | 적용/확인 필요 | `/pii/detect/file`에서 업로드 파일을 `xutf_8`로 텍스트 추출 후 탐지. 지원 포맷은 `xutf_8` 추출 가능 여부에 의존 |
| 첨부파일에 포함된 이미지파일 내 개인정보 탐지 | 미적용 | OCR 파이프라인 없음 |
| 이미지파일 내 개인정보 탐지 | 미적용 | 선명/흐림/캡처 이미지 OCR 로직 없음 |
| 개인정보 입력 시 리턴메시지 표출 | 적용 | API 응답에 타입별 count, matchString, offset, 검증/문맥 필드 반환 |
| 관리자 화면 기록 주민등록번호 마스킹 | 부분 적용 | 일부 trace item 로그는 마스킹 함수가 있으나 API 요청 로그는 원문 일부를 truncate해서 기록하고, 응답에는 matchString 원문이 포함됨. 관리자 화면 마스킹 기능은 없음 |
| 사용자 기록 점검 시 전후 대화 확인 | 부분 적용 | 단일 입력 텍스트 내 주변 문맥 window는 사용. 멀티턴 대화 이력 저장/조회 기능은 없음 |
| 인사 DB 연동 및 부서별 조회 | 미적용 | HR DB 연동/부서별 조회 기능 없음 |
| 특정 직원 및 특정 서비스 예외처리 | 미적용 | 운영 UI/API 기반 직원/서비스 단위 예외처리 기능 없음 |
| 이중화 구성 | 부분 적용 | gRPC scale-out, HAProxy LB 구성 스크립트 존재. 현재 운영 배포에서 활성화 여부는 별도 확인 필요 |
| 탐지 개인정보 항목 수 | 적용 | 기본 응답 기준 9개 타입. 룰 파일 기준 주소/IP까지 포함하면 11개 후보이나 주소/IP는 기본 비활성 |

## 4. 적용 항목 구현 상세

### 4.1 주민등록번호(`SN`)

적용 상태: 적용

지원 형식:

| 형식 | 예시 | 적용 |
| --- | --- | --- |
| 표준 하이픈 | `890512-2054508` | 적용 |
| 하이픈 없음 | `8905122054508` | 적용 |
| 한글 숫자 혼합 | `팔구공오일이-이공오사오공팔` | 적용 |
| 하이픈 주변 공백 | `890512 - 2054508` | 미적용 |

검증 로직:

| 검증 | 구현 내용 |
| --- | --- |
| 길이 | 숫자 정규화 후 13자리 |
| 생년월일 | 앞 6자리와 뒷자리 첫 숫자로 century 계산 후 실제 날짜 검증 |
| 성별/세대 코드 | 뒷자리 첫 숫자 1~8만 허용 |
| 존재불가 월/일 | 월 1~12, 일 1~31 및 실제 날짜 검증 |
| 체크섬 | 기존 부여체계는 체크섬 통과 시만 `SN` 유지 |
| 2020-10-05 이후 | 생년월일이 2020-10-05 이상인 경우 임의번호 부여체계로 보고 체크섬 실패만으로 제외하지 않음 |
| 문맥 | `default` 룰셋에서는 주민등록번호 라벨, 이름+번호 행, 표 헤더, 반복 구조 등을 통과 근거로 사용 |

응답 필드:

| 필드 | 의미 |
| --- | --- |
| `isValid` | 최종 유효 후보 여부 |
| `checksum_status` | `checksum_pass`, `new_system_checksum_skipped` 등 |
| `context_accept_by` | 문맥 통과 근거 |
| `context_pass` | 문맥 통과 여부 |

### 4.2 운전면허번호(`DN`)

적용 상태: 부분 적용

지원 형식:

| 형식 | 예시 | 적용 |
| --- | --- | --- |
| 하이픈 | `11-22-333333-44` | 적용 |
| 공백 | `11 22 333333 44` | 적용 |
| 하이픈 없음 | `112233333344` | 적용 |
| all-zero | `00-00-000000-00` | 제외 |

구현 내용:

| 항목 | 내용 |
| --- | --- |
| 탐지 방식 | 정규식/Hyperscan 기반 후보 탐지 |
| 문맥 필터 | `운전면허`, `driver license`, `license number`, `DL` 등 한/영 라벨 사용 |
| 체크섬 | 미적용 |
| 오탐 제어 | all-zero 제외와 문맥 필터 적용. 제품코드/업무코드 전용 제외 목록은 없음 |

### 4.4 전화번호/휴대폰번호(`MN`)

## 5. 미적용 또는 보완 필요 항목

### 5.1 별도 detector가 없는 항목

현재 별도 detector/rule/checksum이 없는 항목:

| 항목 | 상태 |
| --- | --- |
| 법인등록번호(`CPN`) | 미적용 |
| 외국인등록번호 전용(`FN`) | 적용 |
| 차량번호 | 미적용 |
| 건강/진료 정보 | 미적용 |
| 종교/정치 성향 | 미적용 |
| 제품 모델명 화이트리스트 | 미적용 |
| 공개 전화번호/공개 주소 화이트리스트 | 미적용 |

### 5.2 OCR/이미지 탐지

현재 첨부파일 처리는 다음 순서이다.

1. `/pii/detect/file`로 파일 업로드
2. 임시 파일 저장
3. `xutf_8` 외부 바이너리로 텍스트 추출
4. 추출 텍스트를 일반 PII 탐지 파이프라인에 전달

따라서 이미지 기반 개인정보 탐지는 현재 미적용이다.

| 케이스 | 상태 | 사유 |
| --- | --- | --- |
| 한글/워드/엑셀 등 텍스트 문서 | 적용/확인 필요 | `xutf_8`가 텍스트를 추출할 수 있으면 탐지 가능 |
| 문서 안에 삽입된 이미지 | 미적용 | OCR 없음 |
| 이미지 파일 직접 업로드 | 미적용 | OCR 없음 |
| 흐릿한 사진/화면 캡처 | 미적용 | OCR/이미지 전처리 없음 |

### 5.3 운영/관리 기능

현재 `xcn-pii`는 탐지 API 중심 프로젝트이며, 관리자 운영 화면 기능은 제한적이다.

| 기능 | 상태 | 설명 |
| --- | --- | --- |
| 관리자 화면 기록 조회 | 미적용 | 전용 관리자 화면/DB 없음 |
| 주민등록번호 마스킹 저장 | 부분 적용 | trace item 마스킹 함수는 있으나 요청 로그와 응답 원문은 별도 마스킹 보장 없음 |
| 전후 대화 이력 확인 | 부분 적용 | 단일 요청 텍스트 내 문맥만 사용 |
| 인사 DB 연동 | 미적용 | DB 연동 코드 없음 |
| 부서별 조회 | 미적용 | 부서/조직 필드 없음 |
| 특정 직원 예외처리 | 미적용 | 직원 식별 기반 예외처리 없음 |
| 특정 서비스 예외처리 | 미적용 | 서비스 단위 정책 API 없음 |

## 7. 리턴 메시지 및 로그 보안

### 7.1 API 리턴 메시지

적용 상태: 적용

`/pii/detect`와 `/pii/detect/file`은 다음 정보를 반환한다.

| 필드 | 설명 |
| --- | --- |
| `success` | 처리 성공 여부 |
| `status` | HTTP 성격의 상태 코드 |
| `data` | 타입별 탐지 결과 |
| `*_CNT` | 타입별 탐지 건수 |
| `matchString` | 탐지된 원문 문자열 |
| `start`, `end` | 원문 offset |
| `isValid` | 구조/체크섬 검증 결과 |
| `checksum_status` | 주민등록번호 체크섬 정책 상태 |
| `context_*` | 문맥 필터 점수/통과 근거 |
| `meta` | 룰셋 이름/버전/갱신 시각 |

주의: 응답의 `matchString`은 원문을 그대로 포함하므로 외부 저장/화면 표시 시 별도 마스킹 처리가 필요하다.

### 7.2 로그 보안

현재 요청 로그는 입력 텍스트를 일정 길이로 truncate해서 기록한다. 이는 마스킹이 아니라 길이 제한이므로 주민등록번호가 앞쪽에 있으면 로그에 노출될 수 있다.

보완 권고:

| 보완 항목 | 필요성 |
| --- | --- |
| 요청 로그 원문 마스킹 | 관리자/운영 로그의 개인정보 노출 방지 |
| 응답 저장 시 `matchString` 마스킹 | 탐지 결과 저장소 개인정보 노출 방지 |
| 원문 저장 최소화 | 감사 목적 외 원문 보관 제한 |
| 관리자 화면 권한 분리 | 개인정보 열람 최소권한 적용 |

## 10. 결론

현재 `xcn-pii`는 구조화된 번호/연락처 중심의 PII 탐지 API로 구현되어 있으며, 기본 응답 기준 탐지 항목 수는 9개이다.

적용 수준이 높은 항목은 주민등록번호, 사업자등록번호, 카드번호, 전화번호, 이메일, SSN이다. 운전면허번호, 여권번호, 계좌번호는 구조/문맥 기반으로 동작하지만 전용 체크섬이나 업무별 오탐 검증은 부족하다.

법인등록번호, 차량번호, OCR 이미지 탐지, HR DB 연동, 관리자 예외처리/이력 조회는 현재 미적용이므로 별도 기능 개발이 필요하다. 외국인등록번호 전용 처리는 `FN` 타입으로 분리 적용되어 있다.
