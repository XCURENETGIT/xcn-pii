# 개인정보 문맥 탐지 검증 결과 (2026-08-12)

## 검증 환경

- 서버: `10.100.40.52`
- 이미지: `1.0.8-context-20260812-r2`
- 입력: 끝부분에 유효한 BRN이 있는 52,042자 문자열
- 성공 조건: API 성공 응답 및 `BRN_CNT=1`
- HTTP: 1 Uvicorn worker
- gRPC: 인스턴스당 탐지 worker 4개, 대기 1개, LB replica 3개
- HTTP와 gRPC 모두 영속 연결을 재사용하고 각 측정 전에 warm-up 수행

## 프로토콜 비교

### 동시성 1, 대상별 50회

| 경로 | 성공 | RPS | p50 | p95 | p99 |
|---|---:|---:|---:|---:|---:|
| HTTP | 50/50 | 12.247 | 81.607 ms | 82.212 ms | 82.475 ms |
| gRPC 직접 | 50/50 | 12.039 | 82.931 ms | 83.894 ms | 84.005 ms |
| gRPC LB | 50/50 | 11.926 | 83.632 ms | 85.194 ms | 85.417 ms |

단일 요청에서는 gRPC 직접 경로가 HTTP보다 p50 약 1.3 ms 느렸고, LB 경유 비용이 추가로
약 0.7 ms였다. 탐지 연산이 약 82 ms를 차지하므로 프로토콜 차이는 작다.

### 동시성 4, 대상별 80회

| 경로 | 성공 | RPS | p50 | p95 | p99 |
|---|---:|---:|---:|---:|---:|
| HTTP 1 worker | 80/80 | 12.436 | 321.542 ms | 382.971 ms | 395.859 ms |
| gRPC 직접 | 80/80 | 47.686 | 83.486 ms | 84.399 ms | 84.588 ms |
| gRPC LB | 80/80 | 47.169 | 83.934 ms | 85.425 ms | 86.369 ms |

현재 HTTP는 worker 1개라 처리량이 약 12.4 RPS에서 포화된다. gRPC는 한 인스턴스에 탐지
worker 4개가 있어 동시성 4에서 약 47 RPS를 처리한다.

### 동시성 10, gRPC LB 100회

| 경로 | 성공 | RPS | p50 | p95 | p99 |
|---|---:|---:|---:|---:|---:|
| gRPC LB | 100/100 | 117.043 | 84.294 ms | 86.742 ms | 87.682 ms |

단일 gRPC 인스턴스에 동시성 10을 직접 주면 인스턴스 수용량 5를 초과해
`RESOURCE_EXHAUSTED`가 발생한다. 이는 타임아웃 누적을 막는 의도된 과부하 보호다.

### 임시 HTTP 4-worker 확인

운영 설정을 바꾸지 않고 임시 컨테이너로 확인한 결과 동시성 4에서 33.276 RPS,
p50 119.794 ms였고 메모리는 약 4.56 GiB였다. gRPC 직접 경로의 47.686 RPS보다 낮고 각
HTTP worker가 모델을 따로 보유하므로, 현재는 HTTP worker 증설보다 gRPC LB 사용을 우선한다.

## 문맥 평가 보강

- 대상: 문맥 적용 유형 17종
- 사례: 유형별 양성 4건, 음성 4건, 총 136건
- 추가 경계: 라벨 간격, 이전 행 원거리 부정 표식, 후보 뒤 근거리 부정 표식, 영문 표식 단어 경계
- 결과: TP 68, TN 68, FP 0, FN 0
- `MN`, `EML`, `AN`: 의도적 문맥 제외 정책 유지

이 결과는 합성 회귀 평가 결과다. 운영 precision/recall과 threshold 확정에는 비식별 처리된
실제 대표 표본이 필요하므로 현재 threshold는 변경하지 않았다.

## 잔여 권장 작업

1. 실제 오탐·미탐을 원문 없이 유형, 주변 문맥 템플릿, 기대 판정 형태로 비식별 수집한다.
2. 유형별 양성·음성 최소 50~100건이 모이면 `dataset_kind=representative` 평가셋으로 재평가한다.
3. 24~72시간 동안 gRPC `RESOURCE_EXHAUSTED`, `DEADLINE_EXCEEDED`, p95, 오류율을 관찰한다.
4. HTTP 고동시성 요구가 생길 때만 별도 replica/LB 구조를 검토한다.
